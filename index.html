The problem

A grown product has no system. Building one afterwards is manual work.

In a product that has grown for years, every feature has its own handwriting. Requirements went straight from stakeholders into development, with no design in between. Now design is asked to clean it up.

The reference is the running product.
Screenshots, pages, sometimes only a URL. Someone redraws each screen as components in Figma, element by element.
Figma and code each hold half of the system.
Neither is a reliable source for the other, so they drift apart without anyone noticing.
Converters only go one way.
Most tools move a design into Figma or out of it. Few keep both sides on the same components.

The gap kept coming up across teams, most recently at a cost-management platform for the construction industry with its own software and no design system.

How it works

One pipeline from source to system.

01 · READ

Break the source down

The AI extracts design tokens (colors, typography, spacing, radius, shadows) and detects UI components, grouped as atoms, molecules, organisms and templates.

  • Screenshot · available
  • URL · preview
  • Repository · preview
  • Figma file · via plugin
→
02 · MATCH

Map to a design system

Each detected component is resolved against a component catalog instead of being redrawn freehand. Today that catalog is shadcn/ui with Tailwind.

Figma components and code components then share one vocabulary. Using your own repository as the catalog is the next step.

→
03 · WRITE

Write it where teams work

Figma: components, text styles and color styles, written by the UIPrism plugin.

Code: JSX components and a tokens.css file to download.

Storybook: a live preview with all detected components, their variants and controls.

The interface

Inside the prototype.

Read and match

Tokens and components, each with a confidence level

Colors, typography, spacing, radius and shadows are extracted from the source. Detected components are grouped as atoms, molecules, organisms and templates, mapped to shadcn/ui and previewed in the list. High, Medium or Low shows what to check first.

Write to Figma

Components and styles in the Figma file

The plugin writes components, text styles and color styles into the file, then assembles the dashboard template from them.

Write to Storybook

Every component in Storybook

A live preview lists all detected components with their variants and controls, up to the finished template.

Status · Beta

What works today, and what does not yet.

Available

  • Screenshot import with token extraction
  • Component detection: atoms, molecules, organisms, templates
  • Mapping to shadcn/ui components
  • Figma export via plugin: components, text styles, color styles
  • Code download: JSX and tokens.css
  • Storybook preview

Preview

  • URL import
  • Repository import

Planned

  • Your own repository as the component catalog
  • Your own Figma design system as the component catalog

UIPrism is in beta. It started as a prototype in the Vibe Coding Bootcamp and has been tested with other designers. It is not in continuous use yet. Development continues.

Results are most reliable for single components. Full-page layouts are still being refined.
